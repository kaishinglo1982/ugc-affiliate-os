# Phase 10.1 — Existing-State Inventory & Architecture Map

Status: **completed as architecture inventory; implementation gaps remain for 10.2+**

Issue: #10  
Branch: `phase-10-agentic-automation`

## Objective

Map the existing workflow, agent, tool-governance, approval, budget, queue, audit and idempotency primitives before adding new Phase-10 structures. This inventory is intentionally conservative: existing models must be extended rather than duplicated.

## Confirmed existing primitives

### Workflow persistence

The Prisma schema already contains:

- `WorkflowDefinition`
- `WorkflowStepDefinition`
- `WorkflowRun`
- `WorkflowStepRun`
- workflow states and step types for `AGENT`, `TOOL`, `APPROVAL`, and `CONDITION`

These models are the canonical persistence layer for Phase 10. No parallel workflow tables may be introduced.

### Tool governance

The schema already contains:

- `AgentToolDefinition`
- `AgentToolPolicy`
- `AgentToolCall`
- risk levels
- approval requirement
- per-call cost limit
- per-minute rate limit
- allowed-agent keys

These models are the canonical tool governance foundation. Phase 10 must add enforcement services and tests around them rather than replace them.

### Approval foundation

The shared `Approval` model already supports:

- workspace scoping
- resource type and resource id
- pending/approved/rejected states
- requester and decision metadata
- cost and currency
- expiry
- structured payload

Phase 10 should extend the approval resource enum only where necessary and route all irreversible or high-risk automation through this shared approval mechanism.

### Budget foundation

The schema already contains:

- `BudgetPolicy`
- `CostReservation`
- reservation states `RESERVED`, `CONSUMED`, `RELEASED`, `EXPIRED`

This is the canonical budget-control base. Phase 10 must implement atomic reservation, consumption and release semantics using these models.

### Existing job/idempotency patterns

Existing domain jobs demonstrate reusable patterns:

- `ProductResearchJob` has `correlationId`, unique `idempotencyKey`, attempts, maximum attempts and terminal timestamps.
- `AnalyticsSyncJob` has `correlationId`, optional unique `idempotencyKey`, retry counters, failure code, last error and `nextAttemptAt`.
- `AnalyticsEvent` has a unique `idempotencyKey`.

Phase 10 should standardize these patterns through shared execution helpers instead of creating incompatible job semantics.

### Workspace isolation

The automation-related models consistently carry `workspaceId`. However, schema presence alone is not proof of runtime isolation. Every service query and mutation must filter by workspace and every cross-resource lookup must reject foreign-workspace identifiers.

## Canonical architecture decision

Phase 10 will extend the existing Phase-4 agentic-operations schema. The following are prohibited unless a migration note proves necessity:

- a second workflow definition model;
- a second workflow run model;
- a second generic approval table;
- a second budget-policy or cost-reservation system;
- direct tool execution that bypasses `AgentToolPolicy` enforcement;
- workflow execution without workspace scope, correlation id and idempotency context.

## Required implementation order

1. **10.2** harden and version workflow definitions.
2. **10.3** implement the durable orchestration state machine and worker claiming.
3. **10.4–10.7** add agent routing, tool gateway, approvals and budget enforcement.
4. **10.8–10.10** add resilience, compensation and idempotent side effects.
5. **10.11–10.13** complete audit, kill switches and observability.
6. **10.14–10.15** add control-plane APIs/UI, adversarial tests and production evidence.
